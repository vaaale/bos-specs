Right-click with 3 selected opens the full context menu (Q2=A). Open & Rename are single-only → greyed. Copy / Move / Download / Delete apply to all 3 in one operation. With exactly one item selected every row is enabled and behaves as today (no regression).

Drag-and-drop — within the instance (move to a sibling folder / copy to the same folder) and across two separately-open Files windows. The drag ghost carries the whole selection (count badge). On drop: a different folder = move; the same folder = copy with a non-colliding name (e.g. meeting-notes (1).md). Both views then update without a manual refresh.

Two instances, one shared VFS. Dragged 2 items from the left window into this one → moved (different folder). This view now shows them; the source view drops them — no manual refresh on either.

Copy (same-folder) naming: dropping an item back into its own folder creates name (1).ext, name (2).ext, … — never an overwrite. The drag ghost (not shown separately) shows a count badge ("2 items") and a MOVE/COPY tag. An invalid drop (a file row, the item itself, a descendant of a dragged folder, or a destination that changed mid-drag) is a no-op — items return to origin. Not an invalid target: dropping onto the empty area of the current folder is a same-folder copy.
